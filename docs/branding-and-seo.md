# Brand, icons, SEO and social previews

Code: `brand/build.py` + `brand/scenes/`, files in `web/icons/`, `web/favicon.ico`, `web/manifest.webmanifest`, `web/robots.txt`, `web/sitemap.xml`, head of `web/index.html`, `harness.py` (`static_file`, `_site`).
Tests: `StaticTests` in `test_harness.py` (types, placeholder, Host safety, metadata complete, real image sizes, manifest files, favicon.ico).

## The mark
Since 2026-11-21 the icon is the SHARED Choco icon style: a sky-cyan tile (the dark-mode accent) with a dark LINE glyph, generated by the ChocoHost-Design repo (`brand/spec.mjs` row `ai`, docs `brand.md` there) so every Choco app has the same look. The glyph is still a **speech bubble with a centred tail holding a four-point AI spark** (redrawn as a 2px line icon; the spark is solid). Colours come from the design tokens, not from this repo. The old teal gradient mark and its `BUBBLE`/`spark()` geometry in `brand/build.py` are gone; `mark-dark.svg` and `mark-mono.svg` were deleted (nothing used them).

| file | use |
|---|---|
| `icons/mark.svg` | the glyph alone, black on transparent. Used as a CSS MASK by `.logo` (accent square + glyph in `--primary-foreground`, so it flips with light/dark like the other apps' logo) |
| `icons/icon.svg` | app icon / favicon (rounded tile + glyph) |
| `icons/icon-maskable.svg` | full-bleed version with the glyph inside the 80% safe circle |
| `favicon.ico` | 16, 32 and 48 px PNGs in one file |
| `icons/icon-192.png`, `icon-512.png`, `apple-touch-icon.png` (180, full bleed), `icon-maskable-512.png` | PWA and home-screen icons |
| `icons/og.png` (1200x630) | social preview (Open Graph / Twitter large card). Built here from `brand/scenes/og.html` |
| `icons/screenshot-wide.png`, `screenshot-narrow.png` | install-dialog screenshots listed in the manifest |

To change the icon: change the design repo, `npm run build:brand` there, then `node brand/install.mjs ai <this repo>` (writes the icon files above), then bump `VERSION` in `brand/build.py` and run `python3 brand/build.py stamp` (rewrites `?v=N` in `web/index.html`, `web/manifest.webmanifest`, `web/app.css`; note the `.logo` mask URL in `app.css` is stamped too) and bump the service worker cache name in `web/sw.js`. `python3 brand/build.py svg|icons` now refuses and says so.

### Why the tab may still show the old icon
Browsers keep favicons in their own cache, separate from the page cache, for a long time, and home-screen/app icons and social previews are cached by URL. So every icon URL carries `?v=N`. **When the look changes, bump `VERSION` in `brand/build.py` and run `python3 brand/build.py stamp`**: it rewrites `?v=N` in `web/index.html`, `web/manifest.webmanifest` and `web/app.css`. A new URL is fetched fresh everywhere. (The server ignores the query string.) An already open tab may need one reload; an installed PWA updates its icon after it refreshes its manifest, sometimes only after reinstall.

## "Photographs", not generated art
The preview and store images are screenshots (Firefox, headless) of real pages (the icons are no longer made here, see above); the preview and store screenshots are scenes in `brand/scenes/` built with the app's own CSS and components (`web/js/turn.js`) filled with a sample conversation (a Kyoto trip plan). The wording in the preview only claims what exists: chat for free, sign in for saved chats, web search, documents, scheduled tasks (photos are left out while `vision` is off).
Regenerate the preview and store images: `python3 brand/build.py scenes` (also `stamp`; plain `python3 brand/build.py` does both). Needs macOS with Firefox; it is a dev tool, not run in CI or in the image. Commit the outputs. After a change to the look of the app, rerun `scenes` so the preview matches.

## Page head (`web/index.html`)
- Title `ChocoAI – your AI assistant` (under 60 characters), description (under 160), `robots` index/follow with large image previews, canonical URL, `color-scheme`, theme colours for light and dark, app and Apple web-app tags.
- Open Graph (`og:type/site_name/title/description/url/locale/image` + type, size, alt) and Twitter (`summary_large_image`, title, description, image, alt).
- JSON-LD `WebApplication` (name, url, description, category, any OS, requires JavaScript). No ratings or prices are claimed.
- Icons: `favicon.ico`, SVG icon, Apple touch icon, manifest.
- A visitor without JavaScript sees the static skeleton and a `noscript` line; search engines that run JavaScript see the app. The app is a single page (`/`), so the sitemap has one URL; chats are private and not indexable.

## The site address is filled in when served
Canonical, `og:url`, `og:image`, `twitter:image`, JSON-LD, `robots.txt` and `sitemap.xml` contain the placeholder `__SITE__`; `harness._site()` replaces it on every response (HTML, txt, xml only):
1. `HARNESS_PUBLIC_URL` if set (recommended in production, e.g. `https://ai.chocorot.net`).
2. Otherwise `http(s)://<Host>`; `https` only when `HARNESS_TRUST_PROXY=1` and `X-Forwarded-Proto: https` (the compose file sets this behind Cloudflare).
3. A `Host` that is not plainly a host name (quotes, spaces, `<`, too long, empty) gives "" (relative URLs), so a crafted header can't put text into the page.
So the same files work on localhost, on a test domain and in production, with no domain written in the repo.

## Manifest (`web/manifest.webmanifest`)
`id`, `name`, `short_name`, `lang`, `categories`, `display: standalone`, icons (any 192, any 512, maskable 512, SVG), `screenshots` (wide and narrow, for the richer install dialog), a "New chat" shortcut. Tests check that every icon and screenshot exists and has the declared pixel size.

## Cache and serving
Images (`.png .svg .ico`) are cached for a day (`Cache-Control: public, max-age=86400`); HTML, CSS, JS, manifest, robots and sitemap are always revalidated. If you change an icon and a browser or app keeps the old one, it is the day-long cache or the service worker (network first for files; the offline copy is only a fallback). Social platforms cache previews on their side: after changing `og.png`, ask each platform's debugger to rescrape the URL.

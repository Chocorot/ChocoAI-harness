# Brand, icons, SEO and social previews

Code: `src/app/layout.tsx` (`generateMetadata`, `viewport`), `src/app/page.tsx` (JSON-LD), `src/app/robots.ts`, `src/app/sitemap.ts`, `public/icons/`, `public/favicon.ico`, `public/manifest.webmanifest`.
Tests: none for the head tags yet (checked by hand with `curl`, see "Verified").

## The mark
The icon is the SHARED Choco icon style: a sky-cyan tile (the dark-mode accent) with a dark LINE glyph, generated by the ChocoHost-Design repo (`brand/spec.mjs` row `ai`, docs `brand.md` there) so every Choco app has the same look. The glyph is a **speech bubble with a centred tail holding a four-point AI spark**. Colours come from the design tokens, not from this repo.

| file | use |
|---|---|
| `icons/mark.svg` | the glyph alone, black on transparent |
| `icons/icon.svg` | app icon / favicon (rounded tile + glyph) |
| `icons/icon-maskable.svg` | full-bleed version with the glyph inside the 80% safe circle |
| `favicon.ico` | 16, 32 and 48 px PNGs in one file |
| `icons/icon-192.png`, `icon-512.png`, `apple-touch-icon.png` (180, full bleed), `icon-maskable-512.png` | PWA and home-screen icons |
| `icons/og.png` (1200x630) | social preview (Open Graph / Twitter large card) |
| `icons/screenshot-wide.png`, `screenshot-narrow.png` | install-dialog screenshots listed in the manifest |

To change the icon: change the design repo, `npm run build:brand` there, then `node brand/install.mjs ai <this repo>` and point it at `public/` (it writes the icon files above), then bump the `?v=N` in `src/app/layout.tsx` and `public/manifest.webmanifest` (find them with `grep -rn "v=4" src public/manifest.webmanifest`) and the cache name in `public/sw.js`.

### Why the tab may still show the old icon
Browsers keep favicons in their own cache, separate from the page cache, for a long time, and home-screen/app icons and social previews are cached by URL. So every icon URL carries `?v=N`; a new number is fetched fresh everywhere. An already open tab may need one reload; an installed PWA updates its icon after it refreshes its manifest, sometimes only after reinstall.

## Page head (`generateMetadata`)
- Title `ChocoAI – your AI assistant`, description, `robots` index/follow with large image previews, canonical URL, theme colours for light and dark (`viewport`), Apple web-app tags.
- Open Graph (`og:type/site_name/title/description/locale/image` + size, alt) and Twitter (`summary_large_image`, title, description, image, alt).
- JSON-LD `WebApplication` (name, url, description, category, any OS, requires JavaScript). No ratings or prices are claimed.
- Icons: `favicon.ico`, SVG icon, Apple touch icon, manifest.
- A visitor without JavaScript sees a `noscript` line; search engines that run JavaScript see the app. The app is a single page (`/`), so the sitemap has one URL; chats are private and not indexable.

## The site address (`HARNESS_PUBLIC_URL`)
Canonical, `og:url`, `og:image`, `twitter:image`, JSON-LD, `robots.txt` and `sitemap.xml` are built from `HARNESS_PUBLIC_URL` (for example `https://ai.chocorot.net`) **at request time** (the page, robots and sitemap are `force-dynamic`, otherwise Next would bake in whatever the variable was at build). **Unset: those tags are left out** (no canonical, relative image URLs, empty sitemap). Set it in production. The old `__SITE__`/Host-header fallback is gone.

## Manifest (`public/manifest.webmanifest`)
`id`, `name`, `short_name`, `lang`, `categories`, `display: standalone`, icons (any 192, any 512, maskable 512, SVG), `screenshots` (wide and narrow), a "New chat" shortcut. It is a static file; `background_color` / `theme_color` are the dark `--background` (`#040608`).

## Cache and serving
Next serves `public/` with its own cache headers. If you change an icon and a browser keeps the old one, it is the favicon cache, the `?v=` number was not bumped, or the service worker (network first; the offline copy is only a fallback). Social platforms cache previews on their side: after changing `og.png`, ask each platform's debugger to rescrape the URL.
